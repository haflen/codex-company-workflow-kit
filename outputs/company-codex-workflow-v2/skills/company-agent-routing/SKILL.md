# Company Multi-Agent Entry

Users select this skill and provide a task, audience and materials. Determine the current stage, assign necessary roles, use existing workflows and continue to the agreed endpoint. Do not ask users to select roles, fill dispatch packets or repeatedly say continue.

## Activation and disclosure

Selecting this skill to perform a concrete task, or explicitly requesting multiple agents, grants delegation for that task; do not reconfirm activation. Quoting the skill to discuss, evaluate or edit it does not authorize business-agent dispatch. Ordinary workflows and single-executor mode remain usable. The latest no-agent instruction wins; apply existing cancellation rules, confirm actual stopping and preserve results.

Start with one or two sentences stating the endpoint, planned roles and relevant capabilities. Say dispatched only after a real tool result; update material changes or capability limits. At delivery explain actual participation and findings without exposing the internal task packet as the deliverable.

## Arrange the work

1. Read project context and current materials; establish existing capabilities and the requested changes before planning. Reuse applicable outputs. For an existing system, distinguish reuse, modification, genuinely new work and unverified facts; do not list the whole business flow as new construction. Start from scratch only for an agreed new project or independent rebuild; never use this check to access sources excluded from an isolated rebuild.
2. Use existing phase skills from section 1a of the [multi-agent procedure](../company-expert-routing/references/multi-agent-delivery.md), starting at the earliest missing stage. Use [expert routing](../company-expert-routing/SKILL.md) for expert selection without returning to help for mode selection. Establish the full task sequence, then continue authorized work.
3. Use the procedure's minimum roles: coordinator, executor and a different independent reviewer; add an explorer only for a concrete unknown. One executor may span stages. Use sequential handoffs where parallel benefit is unproven; do not add agents or review rounds to fill a roster. Reuse packet fields and specify sources, editable scope and immutable constraints.
4. Actually dispatch, collect and verify artifacts and raw evidence. Keep shared state single-writer and repair locally. Confirm processes stopped before redispatch after cancellation. Without native tools, disclose single-executor fallback and unmet required independent review; do not simulate separate identities.

## Human-facing delivery

Read the [human-output standard](../../specs/global/assets/human-output-standard.md). For reports, product proposals, instructions or prototypes also use [document writing](../company-document-writing/SKILL.md). Put audience, purpose, existing capabilities, intended change, reader entry and necessary terminology in existing inputs and acceptance for both executor and reviewer.

Integrate contributions into one business narrative, not concatenated agent reports. Within the existing independent review, check understanding from reader-visible text, diagrams and pages: restate the change, usage flow, dependencies and human actions, then check sources for misconceptions, omissions and unsupported promises. Keep this distinct from source-first requirements review; do not call it blind review. Follow the output standard's delivery reading check without adding a writing agent or approval stage.

## Continuation and boundaries

Follow applicable READ-01, AUTH, FLOW, REPAIR, EVIDENCE and WAIT-01 in the [execution policy](../../specs/global/assets/task-execution-policy.md). Decide routine reversible choices within scope; only missing business decisions or authority block dependent actions. Multi-agent mode does not grant implementation, Git, deployment, external messaging, automation or new-chat authority.

When users explicitly request continuing while away, verify actual continuation tools, authorization and local runtime prerequisites; promise cross-turn continuation only after setup succeeds. State files cannot wake a task or guarantee operation with the computer off or asleep. Reuse existing tools, not a new scheduler.

### Response Contract Gate

Before delivery, check results, factual support, reader understanding and actual rendering using the output standard above. Continue authorized work, ask only for genuinely missing decisions and keep internal dispatch records out of user replies.
