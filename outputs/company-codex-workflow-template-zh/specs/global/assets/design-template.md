## 总体技术架构

这张图回答：调用方、应用模块、数据和外部依赖如何协作，本次改动落在哪里？

```mermaid
flowchart LR
    USER["用户/调用方"] --> FE["前端或客户端<br/>本次范围"]
    FE --> API["API/Controller<br/>输入与权限边界"]
    API --> SVC["Domain Service<br/>业务编排，本次范围"]
    SVC --> REPO["Repository/Adapter<br/>数据访问"]
    REPO --> DB[("权威数据存储")]
    SVC -.->|异步/外部| EXT["外部系统或任务"]
```

关键结论：

- 调用入口只负责输入、权限和错误协议，不重新定义业务规则。
- Domain Service 承载本次编排，权威数据通过 Repository/Adapter 访问。
- 外部调用与本地事务边界必须分开说明，失败不能造成伪成功。

## 核心调用时序

这张图回答：一次核心请求如何完成校验、处理、持久化和响应？

```mermaid
sequenceDiagram
    actor User as 用户/调用方
    participant API as API入口
    participant Service as 业务服务
    participant Store as 权威存储
    participant External as 外部依赖
    User->>API: 提交请求
    API->>API: 鉴权与输入校验
    API->>Service: 传递规范化命令
    Service->>Store: 读取并校验当前状态
    alt 业务条件满足
        Service->>External: 执行必要外部调用
        External-->>Service: 返回结果
        Service->>Store: 在明确事务边界内写入
        Service-->>API: 返回业务结果
        API-->>User: 返回可观察成功
    else 条件不满足或依赖失败
        Service-->>API: 返回明确错误语义
        API-->>User: 返回可恢复失败，不伪装成功
    end
```

关键结论：

- 鉴权和输入校验发生在入口，业务条件由业务服务判断。
- 数据写入与外部调用顺序必须匹配幂等、补偿和一致性策略。
- 失败路径返回可识别错误，必要时保留重试或人工恢复依据。
