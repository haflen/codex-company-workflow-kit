## 成果关系与发布流程

这张图回答：需求、代码、文档、脚本和验证如何组成一次可提交、可发布、可恢复的交付？

```mermaid
flowchart LR
    BASE["已确认需求/设计/任务"] --> CODE["代码与配置成果"]
    BASE --> DOCS["权威文档成果"]
    CODE --> SCRIPTS["版本化迁移/数据脚本<br/>如适用"]
    CODE --> VERIFY["自动与人工验证"]
    DOCS --> VERIFY
    SCRIPTS --> VERIFY
    VERIFY -->|通过| CLEAN["清理临时文件和残留进程"]
    VERIFY -->|失败| STOP["停止提交并修复"]
    CLEAN --> COMMIT["本地 commit"]
    COMMIT --> PUSH["推送业务分支"]
    PUSH --> OBSERVE["发布或后续观察"]
```

关键结论：

- 文档、代码和版本化脚本共同构成交付，不以“能运行”替代完整性。
- 验证失败时不得提交完成结论。
- 临时文件、浏览器进程和本地服务在 commit 前按边界清理。
