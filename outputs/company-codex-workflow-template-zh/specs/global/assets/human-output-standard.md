# 回复与文档表达规范

本规范决定面向谁、在哪里、如何表达；阶段技能决定必须做什么检查。技能中的“输出、报告、完成报告、透明度”字段是执行记录要求，不是逐项回复用户的清单。保留原有验收、授权、图表和证据要求，不增加确认阶段。

工作流任务开始时，按入口规则用一两句说明普通工作流或多 Agent 协作、负责角色及当前相关能力；结束时说明实际使用与检查结果。此简短用户告知保留，内部skill标识、路径、等级和逐项审计仍放执行记录。普通问答无需重复模式声明，已授权协作不增加确认。

## 面向用户的回复

先写一句话结论，明确对象、当前结果及能否继续；再按需要解释完成内容、依据、未验证项的实际影响；最后给下一步建议，写清责任方、动作和前置条件。

正式收尾可用“一句话结论、这次完成了什么、需要你注意什么、你现在需要做什么”四部分，也可按内容组织。普通问答和工作中更新用自然段即可；无实际风险或用户待办时不填空话。用户要求详细时展开原因、证据和选择依据，不扩写内部流程清单。

- 按既有验收范围区分开发、验证、提交、合并、部署和上线观察。阻断必须说清阻断哪一步、原因是什么；不把局部待确认写成全部工作无效，也不擅自新增或降低验收条件。
- 数字说明验证了什么行为、在什么环境、还不能证明什么；部分包含在总数中时明确写“其中”，不相加。隔离数据库、真实接口、直接测试消息和生产自动通知分别举证。
- 下一步遵循已有授权继续执行；只有确需用户补充信息、选择或授权时才交给用户。已有前置条件未满足时，不推荐跳过它部署。不要要求用户重复回复“继续”或照抄口令。
- 中文对话使用中文标题、状态、解释和链接文字。内部状态先译出含义；精确状态码、代码、命令、文件路径、接口字段、错误原文和专有名称在核查或操作需要时保留，并解释用途。不要把英文全禁，也不要把内部英语字段搬进普通回复。
- 说明实际问题、机制与影响；不用“闭环、收口、水位、饿死”等词替代解释。例如“一个项目检查失败时，其他项目仍会继续检查”。

## 阶段收尾的下一步

阶段完成、交付总结、因阻塞停下或回答“下一步做什么”时，将下一步放在回复的最后一个独立段落，以 **下一步：** 开头。写一个主要动作，明确责任方及必要前提；无需用户操作时也明确说明。不把这条收尾要求扩展为正文固定标题。

| 当前状态 | 收尾内容与执行 |
| --- | --- |
| 已有授权且前置条件满足 | 写明“我接下来……”及具体动作，在同一授权范围内继续执行，不把进度更新当作结束任务，不等用户重复回复“继续” |
| 需要用户处理 | 写明需要用户提供的信息、决定或操作，以及它阻断哪一步；只请求缺失项，不新增审批或扩大授权 |
| 约定范围全部完成 | 明确“本任务已完成，你现在无需操作”；不为了保留下一步而制造额外任务 |

普通问答和工作中更新保持简洁，不强制增加该段；实际发生阶段收尾或阻塞时按上表处理。已约定但暂不具备条件的观察或验收，写清触发条件与责任方；没有真实建立执行机制时，不承诺自动监控或日后通知。候选修复、分支整合、提交、推送、部署各按事实陈述，未完成约定交付不能写“全部完成”。

发送前检查：读者能否一眼找到下一步、知道由谁做及是否需要自己操作？不清楚就重写该段。此规则只约束对话收尾，人类文档仍按文种组织。

## 三种材料，按用途保存

| 材料 | 必须保留 | 保存位置 |
| --- | --- | --- |
| 用户回复 | 结论、必要依据和影响、下一步建议 | 对话；只链接主要成果 |
| 人类文档 | 支持读者评审、决策或操作的完整内容 | 现有模块/版本归属；明确读者和用途 |
| AI 接续与内部执行记录 | 授权、阶段、真实调用、候选指纹、证据、失败尝试和接续位置 | 复用已有任务日志或证据记录；需要时参考 execution-record-template.md |

技术内容不等于 AI 内容。人类技术文档保留图表、公式、字段、接口、异常逻辑；部署说明保留准确路径、命令和必要校验值。读者不需要的技能调用、透明度等级、代理策略、逐文件哈希清单放在内部记录；默认不在回复或人类文档后附审计清单，也不用折叠区或隐藏注释藏它。

普通问答不创建文件，小修复不自动创建人类版与 AI 版两套文档。已有内部记录可续写；确需新建时沿用文档归属规则。执行记录引用权威规格，不另写业务规则或另一套当前结论。不得只说“已另存”而没有实际写入。

用户明确索要审计或交接胶囊时，按请求提供精确记录，并与人类结论分开说明用途；这是指定交付对象，不自动扩散到其他回复和文档。

## 人类文档的写法

- 标题和章节顺序可按读者调整，模板栏目不是成稿的固定格式；内容、证据和适用图表要求以 document-standard.md 为准。改名或精简不得规避验收条件、风险或必要技术规格。

- 开头给当前结论、适用版本/时间、读者和用途。历史快照标明仅反映当时；当前报告不堆叠多轮相互冲突的结论。
- 决策或汇报稿写问题、调整、预期收益、范围、成本/依赖、待决事项和推进建议。设计进展不写成已交付效果；未知预算、日期不编造。
- 验收稿写范围、候选版本、各项结果、关键证据、未验证影响与下一步。正文保留可辨认版本和证据链接，详细分支/差异/逐文件指纹放到所链接内部记录。
- 操作指南逐步写操作位置、动作或命令、预期结果、继续/停止条件、出错后的恢复方法。查询必须能区分新旧记录并支持判断；时间阈值引用已确认依据，未知阈值说明尚未确认，不自造标准。占位参数标明如何取得及替换。
- 按 document-standard.md 保留对应图表和技术精度。图前说明问题，图后解释必要结论；不用固定条数凑文字。
- 更新结论时同步状态表和下一步，并关联固定版本证据；历史结论移至历史记录，保留来源。链接必须适合受众且可访问，对外稿不夹带内部路径或隐藏追溯注释。

## 显示与发送前检查

使用目标界面支持的普通 Markdown。用户交付正文不使用 HTML 折叠标签 details/summary 或隐藏注释；只有用户请求讲解或编辑相关代码时才在代码示例保留原文。图表内部必要语法与正文布局分开处理。

先检验链接、图表和显示效果。无法检查时记录具体未验证部分，不能把源码存在当成渲染通过。审阅者应能从交付内容直接回答：当前结论是什么？依据是什么？还差什么及影响？现在由谁做什么？任一答案要猜测、与证据矛盾、或需要先删除内部内容才能使用，就重写对应部分。结构与关键词检查不能代替这个判断。

例：应用侧专项验证已通过，正式验收还差群内双方负责人覆盖确认。235 项测试中有 61 项使用隔离数据库；收到直接测试卡只证明这次发送成功。下一步由发布负责人确认群成员，材料整理按既有授权继续；确认完成后再按既定部署流程操作。新版生产调度与自然恢复仍按原约定在上线后观察。

## 交付阅读检查

本节适用于给人阅读、讲解或操作的交付，尤其是多角色合成的报告、产品方案与原型；机器交接记录不套此检查。

- 先让读者知道已有基础、本次具体变化和推荐结论，再沿一个实际使用过程展开。旧系统改造从已有页面、流程与代码证据出发；未核实的能力明确标注，不把未知写成缺失或待新建。新项目不虚构既有基础。
- 章节按读者的问题和操作顺序组织，不按代理分工、测试编号或材料到达顺序拼接。跨角色交付由主代理统一术语与叙述；需要流程总览时在细节前给图，并把图中步骤对应到真实章节或原型入口，不为短答强加图。
- 界面和正文使用读者熟悉的完整表达。比如“未载样本”按实际原因写成“这个时段还没有演示数据”或“这项结果尚未收到”；两种情况不能混写。必要的技术名词解释它影响哪个操作或决定，准确字段保留在技术段；不靠替换禁词、删条件或把文字缩短来冒充易读。
- 区分业务范围和代理权限：产品不支持什么、上线依赖什么，会影响读者判断，应保留；“不提交 Git、不向同事发送、只允许写某文件”和“这些未知项不妨碍先交稿”属于代理执行约定或作者说明，放执行记录及必要的用户进度回复，不写进给同事的产品正文。用户要的就是操作规程或授权说明时，相关权限才是正文内容。
- 产品正文描述功能和变化。来源裁定、历史审定、作者辩解、代理自评分放内部记录；会影响读者决定的边界仍就地写清。例如排期待评估，就说“应用和算法评估接口改造后确定排期”，不以“本次不承诺上线日期”代替安排。
- 写完后，按读者实际拿到的入口走一次：先只看成稿、图和页面，复述“已有的是什么，这次改什么，用户怎样完成工作，哪里需要配合或决定”。记录具体句子/页面引起的歧义和无法回答的问题，再对照来源纠正。技术操作稿还应能据文稿找出操作位置、预期结果及失败处理。不要让读者靠作者口头补课或隐藏日志才能理解。

多 Agent 已有独立审查时，将上述阅读检查交给未参与该稿写作的审查者，复用同一审查，不额外增加角色或轮次。事实审查仍先独立读来源；读者检查阶段以成稿为理解依据并明确此前接触来源的限制，不冒称盲测。主代理用复述及来源判断歧义，定点修订后只复查受影响部分。普通工作流由当前执行者做同样检查，如实称自查。

不以“链接能打开”“检查项全过”“出现指定关键词”证明读者能理解；分别说明事实核对、内容理解与实际显示检查。代理复述只能证明该次检查的发现，不能替真人认可。用户指出看不懂时撤回相应“可直接使用”的判断，检查同类问题所在章节及相关页面，而不只改被点名词句；原稿留在既有历史记录，不再生成多个并列当前版本。


## 实际使用反馈

收到影响交付的实际反馈、恢复相关任务或处理同类交付时，按[经验候选的反馈复用与规则精简](experience-candidate-template.md)续写已有内部记录并核对后续结果。先修当前成果；不要求用户填表，反馈本身不授权改技能，不为追踪反馈新增后台安排。
