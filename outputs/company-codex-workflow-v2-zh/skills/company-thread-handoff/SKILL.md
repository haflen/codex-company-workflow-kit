# 公司任务对话交接

## 核心原则

交接只传递继续当前主任务所需的最小状态。项目事实优先于旧对话摘要；交接不产生新的实现授权。

## 模式判断

| 场景 | 模式 | 动作 |
| --- | --- | --- |
| 准备开启新对话、暂停或转交任务 | 导出 | 生成结构化交接摘要和新对话启动提示词 |
| 已粘贴交接摘要，或要求读取 `.codex/handoff/current.md` | 接手 | 先验证当前状态，再决定继续、确认或停止 |

## 交接等级

- `quick`：纯讨论，无代码或配置改动，无阶段切换、未完成验证或运行中服务。
- `full`：存在代码/配置改动、未提交文件、阶段切换、范围变化、验证缺失、运行中服务，或生产、数据、权限、安全、金额、计算口径、架构、性能、跨系统风险。

用户不需要选择等级，由本 skill 自动判定。

## 导出流程

1. 识别当前唯一主任务；其他相关内容放入“旁支事项”，标记为“未纳入当前范围、未经授权”。
2. 只读取主任务所需的 Git 状态、关键文件、权威文档、验证结果和运行状态，不全量扫描项目或复述完整对话。
   - `quick` 且用户未提供具体项目路径时，不检查 Git 或扫描文件，只使用当前对话中已给出的事实。
3. 将信息分为“已验证事实”“旧对话判断”“待确认事项”。不得补写对话中没有确认的接口、字段、成功标准或实现方案。
   - “待确认事项”只列继续当前任务的直接阻塞，不扩展通用需求检查清单。
4. 判断旧实现授权是否仍适用于当前范围。范围变化后的新增内容默认未授权。
5. 自动选择 `quick` 或 `full`，输出交接摘要和可直接粘贴的新对话启动提示词。
6. 默认只在回复中输出。仅当用户明确要求落盘时，才创建或覆盖 `.codex/handoff/current.md`。

## 接手预检

1. 检查交接是否包含生成时间、当前主任务、当前状态和下一步。
2. 核对项目路径、Git 分支、工作区、关键文件、未完成任务、权威文档和阶段授权。
3. 对高风险结论深入验证；无法验证的内容保持“未验证”，不能升级为事实。
4. 输出“相符项、变化项、无法验证项”。
5. 按风险决定：低风险差异说明后继续；中风险差异重新验证并调整下一步；高风险差异停止并要求用户确认。

高风险差异包括：分支不一致、范围变化、实现授权失效、关键文件被其他任务修改、权威文档冲突，或交接要求编码但阶段/验证条件不满足。

## 新对话启动提示词

```text
请使用 company-thread-handoff 接手以下交接内容。先按风险分级核对项目路径、Git 分支、工作区、关键文件、未完成任务和实现授权；输出相符项、变化项和无法验证项。项目当前事实优先于交接摘要。旁支事项未经授权，不得执行。确认可以继续后，再进入交接中建议的正式 workflow。

<粘贴交接摘要>
```

启动提示词只输出上述短前缀，不得再次复制交接摘要。交接摘要在回复中只出现一次。

## 文件与权限边界

- 不自动写文件；用户明确要求时只覆盖 `.codex/handoff/current.md`。
- 不自动创建历史交接文件、修改 `.gitignore`、归档到 `docs/`/`specs/`、提交 Git、创建新 Codex 任务或跨任务发送消息。
- 不用交接摘要替代 `company-context-index`、正式需求/设计/任务文档或阶段确认。
- 不把范围变化之前的实现授权继承给新增范围。
