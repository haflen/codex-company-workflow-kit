# 公司任务对话连续性与交接

## 核心原则

先选择连续性机制，再决定是否生成摘要。完整历史用 Codex 原生继续或 fork；干净上下文才使用交接胶囊。项目事实优先于历史和摘要；交接不产生新的实现授权。

## 第一步：选择用户要的结果

用户选择结果，不需要理解底层命令。意图明确时直接执行；意图不明确时，先推荐一项并只问一次确认。

| 用户实际需求 | 连续性路由 | 摘要策略 |
| --- | --- | --- |
| 稍后继续同一个任务 | `resume` | 不生成；提示从任务列表继续原任务 |
| 当前任务太长，但目标不变 | `compact` | 优先使用 Codex `/compact`；不可用时退回 `standard` 交接 |
| 开新任务且完整历史不能丢 | `fork` | 使用 Codex fork；只补充 fork 未覆盖的最终锚点 |
| 开干净的新任务，只保留决策和进度 | `handoff` | 生成 `quick`、`standard` 或 `decision-rich` 胶囊 |
| 目标任务已经创建 | `handoff` | 不能事后注入完整历史；发送一个完整胶囊并校验接收 |

可向用户展示：

1. `继续原任务，不创建新任务。`
2. `压缩当前任务后继续。`
3. `完整继承历史并创建新任务。`
4. `创建干净交接，只保留关键决策和进度。`

没有偏好时：目标仍相同且只担心长度，推荐 `compact`；明确要求全部历史，推荐 `fork`；进入新里程碑或希望减少 token，推荐 `standard handoff`。

## Codex 原生连续性规则

- `resume`：不生成交接摘要；指导用户继续原任务。当前环境有对应任务工具时使用原生能力，不伪造命令执行结果。
- `compact`：只用于目标、范围和任务主线不变的当前任务。压缩前确保关键决策、未完成事项和项目事实已进入摘要或权威文档。
- `fork`：仅在用户明确要创建新任务并继承完整已完成历史时使用。调用 `fork_thread` 前说明 fork 会保留已完成历史；源任务仍在运行时，活动轮次不会被复制，完成后必须向子任务补发最终锚点。
- 原生任务工具不可用时，明确说明限制并退回 `handoff`，不得声称已完成 resume、compact 或 fork。

## 交接胶囊等级

- `quick`：纯讨论或低风险状态，只包含目标、当前状态、下一步、关键文件和直接阻塞。
- `standard`：默认。存在代码、配置、未提交改动、阶段切换或验证状态时使用；增加决策、约束、授权、证据、未完成事项和风险。
- `decision-rich`：产品边界、架构、业务规则、计算口径、数据、安全、生产、跨系统、多项被否方案，或用户明确不希望重新讨论时使用；增加被否决/延期方案及原因、争议点和不可无证据重开的决策。

优先保证召回率。对是否影响后续判断没有把握的信息，保留到 `standard` 或 `decision-rich`，不要为了短而删除。

## 生成胶囊

1. 识别唯一主任务；旁支标记为“相关但未纳入当前范围、未经授权”。
2. 按风险读取必要的项目路径、Git 状态、关键文件、权威文档、验证和运行状态，不全量复述工具日志。
3. 分开记录“已验证事实、历史判断、待确认事项”。不得补写未确认的接口、字段、成功标准或实现方案。
4. 重新判断阶段许可和实现授权；范围变化后的新增内容默认未授权。
5. 生成一个不可拆分的胶囊。启动指令和摘要必须在同一块中，不再分别输出“短前缀 + 另一份摘要”。

### `quick` 契约

控制在 8-12 个短行：

- 工作流层：`company-thread-handoff`
- 连续性路由：`handoff`
- 摘要等级：`quick`
- 生成时间：
- 当前主任务与目标：
- 当前状态 / 已完成：
- 下一步与完成条件：
- 关键文件：
- 已验证事实 / 历史判断 / 待确认事项：
- 旁支事项：相关但未纳入当前范围、未经授权
- 知识边界：掌握本胶囊覆盖的历史决策，不包含未记录的逐字过程

### `standard` 增强字段

- Goal / Context / Constraints / Done when：
- 项目路径、Git 分支、HEAD 与工作区：
- 当前 workflow、阶段许可与实现授权：
- 已确认决策和不能越过的边界：
- 权威需求、设计、任务、业务规则与公共入口：
- 验证等级、证据、未验证项和剩余风险：
- 未完成任务、阻塞和下一正式 workflow：
- 运行中服务、端口、浏览器和测试进程：
- 文档与实现漂移：

### `decision-rich` 增强字段

- 被否决或延期的方案、原因和重新打开条件：
- 历史争议点与最终结论：
- 关键业务规则、计算口径、数据/权限边界：
- 容易被误解但已确认的表述：
- 未记录的历史信息边界：

所有等级都必须附一条接手指令：先验证当前项目事实，再复述知识校验字段；未通过前不得执行高风险动作。

## 传输与接收校验

传输状态必须显示为：`已生成 -> 已发送/待手动粘贴 -> 已读取 -> 语义校验通过/未通过`。

- 只有用户明确要求传到新任务，且目标任务 ID 已知时，才可使用 `send_message_to_thread`。
- 用户明确要求创建新任务且选择 `fork` 时，才可使用 `fork_thread`；不要用空白 `create_thread` 冒充完整继承。
- 没有任务工具或目标 ID 时，输出一个可整体复制的胶囊，不得拆成多个消息。
- 发送后使用可用的 `wait_threads` 或 `read_thread` 检查目标响应；不能检查时标记“待用户在目标任务确认”。

目标任务必须复述以下六项，作为语义校验：

1. 当前目标与完成条件。
2. 已确认关键决策。
3. 禁止突破的约束和范围。
4. 项目、分支、工作区、关键文件与验证状态。
5. 未完成事项、风险和下一步。
6. 当前阶段许可与实现授权。

缺项或理解冲突时，只发送差异补充并重新校验，不要求用户重新解释整段历史。

目标任务通过后使用准确表述：

```text
我已掌握交接胶囊覆盖的历史决策和当前状态；不掌握未被交接记录的逐字过程。接下来以当前项目事实和权威文档为准。
```

不得笼统说“我不知道历史”，也不得声称知道未被 fork 或胶囊覆盖的内容。

## 接手预检

1. 检查胶囊的生成时间、目标、状态、下一步、摘要等级和知识边界。
2. 核对项目路径、分支、HEAD、工作区、关键文件、未完成任务、权威文档和授权。
3. 高风险结论深入验证；无法验证的内容保持“未验证”。
4. 输出相符项、变化项、无法验证项，再完成六项语义校验。
5. 低风险差异说明后继续；中风险重新验证；分支、范围、授权、关键文件、权威文档冲突等高风险差异停止确认。


## 人类优先输出

最终回复先使用：`一句话结论`、`这次完成了什么`、`需要你注意什么`、`你现在需要做什么`。用业务结果和用户影响表达，只给一个主要下一步；首次出现的内部术语必须解释。随后把 Superpowers、专家调用、命令、路径、哈希、验证证据和内部 workflow 字段放入 `技术审计附录`，不得把内部 workflow 字段逐项倾倒到人类摘要，也不得用审计字段代替人类摘要。


### 回复契约门禁

- 触发范围：本轮正式完成或阶段收尾、用户明确索要进度总结、阻塞结论或下一步方案，以及包含审计字段的成段回复。
- 1-2 句的工作中更新和普通问答始终不触发固定格式，即使提到当前结果、风险或下一步；但不得在轻量回复中附带完整审计明细。
- 用户要求“详细一点”时，只增加四段正文或 `技术审计附录` 的深度，不得删除、改名或调换四个标题。
- 审计字段只能出现在 `技术审计附录`，不得与四段人类摘要并列或抢在其前。
- 发送前检查四个标题是否齐全且顺序正确、风险是否翻译为实际影响、是否只有一个主要下一步；任一不满足时先重写再发送。

## 透明度输出

- 工作流层：`company-thread-handoff`
- 连续性路由：`resume / compact / fork / handoff`
- 摘要等级：`无 / quick / standard / decision-rich`
- Codex 原生能力：建议 / 实际调用 / 不可用及回退
- Superpowers 叠加：通常无；这是连续性与事实传递，不替代正式 workflow
- 传输状态：
- 语义校验：通过 / 未通过 / 待确认
- 下一步：

## 文件与权限边界

- 默认不写文件；用户明确要求时只覆盖 `.codex/handoff/current.md`。
- 不自动创建历史交接文件、修改 `.gitignore`、归档到 `docs/`/`specs/` 或提交 Git。
- 创建、fork 或发送到其他任务必须有明确用户意图；不得静默操作。
- 不用胶囊替代 `company-context-index`、正式需求/设计/任务文档或阶段确认。
- 不把范围变化之前的实现授权继承给新增范围。
