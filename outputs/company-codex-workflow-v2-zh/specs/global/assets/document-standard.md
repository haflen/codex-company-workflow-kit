# 公司正式文档阅读与图表标准

## 适用范围

本标准适用于新建或发生实质更新的需求、业务规则、技术设计、数据模型、API 契约、任务计划、Spike、Hotfix、需求原型记录、交付收口和项目上下文索引。历史文档不自动重写。

## 统一阅读顺序

1. 先看结论。
2. 本次变化。
3. 建议阅读路径和图例。
4. 核心 Mermaid 图。
5. 场景、流程和逻辑解释。
6. 详细规格。
7. 异常、风险和验证。
8. 评审结论和下一步。

## 元信息与追溯编号

每个 feature 或 milestone 定义稳定的 `work-item-id`。跨文档引用使用 `<work-item-id>/<本地编号>`。

| 对象 | 本地编号 | 完整引用示例 |
| --- | --- | --- |
| 流程节点 | `F-nnn` | `STP-M1/F-001` |
| 业务规则 | `BR-nnn` | `STP-M1/BR-001` |
| 验收标准 | `AC-nnn` | `STP-M1/AC-001` |
| 设计决策 | `D-nnn` | `STP-M1/D-001` |
| API 契约 | `API-nnn` | `STP-M1/API-001` |
| 实现任务 | `T-nnn` | `STP-M1/T-001` |
| 测试或验证 | `TC-nnn` | `STP-M1/TC-001` |

编号发布后不得因排序变化而重排；废弃对象保留编号并标记状态。跨文档引用还必须提供文档路径或章节链接。

## 本次变化

“本次变化”固定放在“先看结论”之后。元信息中的“对比基线”记录上一确认文档路径和 Git commit；初版写明“初版，无对比基线”。

| --- | --- | --- | --- | --- |

## Mermaid 规范

- 图前写明要回答的问题，图后给出 3 至 5 条关键结论。
- 节点优先使用中文业务名称，代码名放在第二行或括号中。
- 一张图只回答一个主要问题；超过约 20 个节点时拆成总图和局部图。
- 不依赖颜色表达唯一语义，使用线型、标签和文字共同说明。
- 需求使用业务流程图；技术设计使用架构图和时序图；数据模型使用关系图和形成时序；其他文档使用其类型规定的图。
- 无法完成渲染检查时必须标记“Mermaid 渲染：未验证”，不能描述为已通过。

## 图表豁免

只有用户明确说明不需要某张图时才允许豁免。豁免记录必须包含用户、图表对象和原因。AI 不得因任务简单、时间紧或技术路径唯一自行豁免。

## 复杂度与篇幅

- L1 可以合并相邻章节，但结论、对应图、关键规则、验证和下一步不能省略。
- L2 使用完整模板结构。
- L3 在完整结构上深入说明跨域关系、迁移、并发、恢复、版本和一致性。

复杂度只决定展开深度，不改变图表和证据要求。

## 文档质量门禁

| 门禁 ID | 检查项 | 通过标准 |
| --- | --- | --- |
| `DOC-G01` | 结论结构 | `先看结论` 非空，并包含问题、结论、影响和确认点 |
| `DOC-G02` | 需求图表 | 存在目标业务流程 Mermaid 图，或有用户明确豁免 |
| `DOC-G03` | 技术图表 | 分别存在总体架构图和 `sequenceDiagram`，或有对应豁免 |
| `DOC-G04` | 类型化图表 | 数据和其他正式文档包含本类型规定的图，或有用户明确豁免 |
| `DOC-G05` | 豁免 | 记录用户、对象和原因；AI 自行判断无效 |
| `DOC-G06` | 图文一致 | 图中节点、状态、表和接口均有正文解释 |
| `DOC-G07` | 主链与异常 | 正常路径和关键异常均有明确行为 |
| `DOC-G08` | 追溯格式 | 本地编号格式正确；跨文档引用包含 `work-item-id` |
| `DOC-G09` | 追溯完整 | 流程、规则、AC、设计、任务和测试可以互相定位 |
| `DOC-G10` | 可见结果 | 技术结构能追踪到页面、接口或业务结果 |
| `DOC-G11` | 渲染 | Mermaid 已渲染检查；否则明确标记未验证 |
| `DOC-G12` | 漂移 | 文档、脚本、代码和实际路径没有明显冲突 |

## Workflow 责任

- `company-feature-requirements`：`DOC-G01`、`DOC-G02`、`DOC-G05` 至 `DOC-G12`；生成业务规则时加 `DOC-G04`。
- `company-feature-design`：`DOC-G01`、`DOC-G03`、`DOC-G05` 至 `DOC-G12`；涉及数据模型或独立 API 契约时加 `DOC-G04`。
- 规划、原型、Spike、上下文索引和交付收口：`DOC-G01`、`DOC-G04` 至 `DOC-G12`。
- Bugfix 默认检查 `DOC-G06` 至 `DOC-G12`；生成 Hotfix 报告时增加 `DOC-G01`、`DOC-G04`、`DOC-G05`。
- 实现只检查本轮更新的权威文档：`DOC-G06` 至 `DOC-G12`。
- 健康检查诊断 `DOC-G01` 至 `DOC-G12`，默认只报告，不自动重写。

## 人工阅读检查

结构门禁不能代替人工判断。阶段结束前仍需确认：业务、产品、开发和测试是否能从结论、图表、正文和追溯关系得到同一套理解。
