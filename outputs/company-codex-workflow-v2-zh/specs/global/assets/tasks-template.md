## 任务依赖与执行停点

这张图回答：哪些任务串行、哪些可以并行，何时必须验证或让用户确认？

```mermaid
flowchart LR
    T001["T-001<br/>建立最小失败案例"] --> T002["T-002<br/>实现核心行为"]
    T002 --> T003["T-003<br/>集成与契约验证"]
    T002 --> T004["T-004<br/>界面或消费方适配"]
    T003 --> GATE{"验证与确认停点"}
    T004 --> GATE
    GATE -->|通过| T005["T-005<br/>回归与文档同步"]
    GATE -->|失败/范围变化| STOP["停止并返回设计或规划"]
```

关键结论：

- 核心行为先有失败案例或验证锚点，再进入实现。
- `T-003` 与 `T-004` 只有在文件和状态边界独立时才可并行。
- 验证失败、范围变化、V3 风险或用户确认点命中时必须停止。
