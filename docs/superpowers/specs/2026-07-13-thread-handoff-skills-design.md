# Codex 长对话任务交接 Skills 设计

## 背景

当一个 Codex 对话过长时，用户往往需要开启新对话继续工作。新对话无法可靠继承旧对话中的当前目标、已确认决策、验证证据、未完成任务和执行边界。直接复制完整聊天记录会带入大量噪声，并可能让新对话把已放弃方案、旁支讨论或过期实现授权当作当前事实。

现有 `company-context-index` 负责项目级长期上下文，`personal-memory-index` 负责个人项目长期记忆，阶段交接口令负责需求、设计、任务和实现之间的流程切换。它们都不适合承担“旧对话到新对话”的临时任务状态传递。

因此新增两个不同严格度的任务交接 skills：

- `company-thread-handoff`：公司项目使用，强调阶段、授权、证据、Git 状态、文档一致性和风险控制。
- `personal-thread-handoff`：个人项目使用，强调低摩擦、最小上下文、下一步动作和快速续接。

两个 skills 共享核心交接协议，但保持不同的输出严格度。

## 设计原则

1. 交接解决的是临时状态传递，不是新增正式项目文档。
2. 默认只在对话中输出摘要，不自动创建文件。
3. 用户明确要求落盘时，只覆盖 `.codex/handoff/current.md`，不按对话生成多个文件。
4. 长期归档必须单独触发，不自动写入 `specs/`、`docs/` 或 Git。
5. 交接以当前主任务为唯一执行主线。
6. 相关旁支只作为未授权背景，不自动转化为新任务。
7. 新对话必须按风险验证交接内容，不能盲目信任旧摘要。
8. 项目当前事实与交接摘要冲突时，以重新验证的项目事实为准。
9. 不复述完整对话，不重复项目已有文档，只提供继续工作所需的最小信息。

## 能力边界

### `company-thread-handoff`

适用于：

- 公司项目长对话准备切换到新对话。
- 一个阶段结束但后续任务尚未完成。
- 存在未提交代码、未完成验证、运行中服务或待确认事项。
- 任务将交给其他成员或另一个 Codex 对话继续。
- 对话已经出现状态遗忘、重复读取、范围混淆或授权漂移。

公司版必须关注：

- 当前 workflow 与阶段。
- 需求、设计、任务和实现授权状态。
- 权威文档及文档与实现的一致性。
- Git 分支、工作区改动和关键文件。
- 验证证据、未验证项和剩余风险。
- 运行中的服务、端口和清理要求。
- Superpowers、专家 skills、插件及其他能力的实际调用情况。

### `personal-thread-handoff`

适用于个人项目或个人任务的新对话续接。默认只保留：

- 当前目标。
- 当前进度。
- 最近完成事项。
- 关键文件与命令。
- 阻塞和待确认事项。
- 下一步动作。
- 未纳入范围的旁支事项。

只有存在代码改动、未提交状态、验证失败或用户明确要求时，个人版才增加 Git 和验证细节。

## 共享交接协议

两个 skills 均输出以下核心字段：

1. `当前主任务`：一句话说明最终目标。
2. `当前状态`：任务停在什么位置。
3. `已完成`：仅列与主任务直接相关的成果。
4. `下一步`：新对话接手后的第一项具体动作。
5. `关键文件`：只列继续任务必须读取的文件。
6. `已验证事实`：附命令、文件、测试或结果证据。
7. `旧对话判断`：尚未由项目事实重新验证的分析结论。
8. `待确认事项`：不得当作事实继承。
9. `旁支事项`：统一标记为“未纳入当前范围、未经授权”。
10. `新对话启动提示词`：用户可直接粘贴到新对话。

公司版在共享字段上增加：

- 项目绝对路径与当前 Git 分支。
- 工作区改动、未提交文件和并发修改风险。
- 当前 workflow、阶段许可和实现授权状态。
- 权威需求、设计、任务、业务规则和公共入口文档。
- 已执行验证、未执行验证和验证等级。
- 运行中服务、端口、浏览器或测试进程。
- 文档与实现漂移。
- 能力调用透明度信息。
- 新对话接手预检清单。

## 输出分级

用户不需要选择等级，由 skill 自动判定。

### `quick`

用于纯讨论、低风险任务、无代码改动或短期暂停。输出最小摘要，不创建文件。

### `full`

命中以下任一条件时使用：

- 存在代码或配置改动。
- 存在未提交文件。
- 任务跨越 workflow 阶段。
- 当前范围发生变化。
- 验证失败、验证缺失或仍有未验证项。
- 存在运行中服务、端口或浏览器进程。
- 涉及生产、权限、安全、数据、金额、计算口径、架构或跨系统风险。
- 新对话需要接替实现工作。

## 触发模式

采用混合触发模式。

### 用户主动触发

推荐说法：

```text
生成当前任务交接摘要，我准备开新对话。
```

需要落盘时：

```text
生成当前任务交接摘要，并覆盖 .codex/handoff/current.md。
```

### Workflow 主动提醒

`company-workflow-help` 和 `personal-workflow-help` 在以下场景提醒用户生成交接摘要，但不自动生成、不自动写文件：

- 用户说“下次继续”“先停这里”“换个对话接着做”。
- 当前任务刚完成一个阶段，但后续任务仍较多。
- 即将切换需求、设计、实现或 bugfix 阶段。
- 对话已出现状态遗忘、重复读取或范围混淆。
- 存在未提交改动、运行中服务或未完成验证。

Skill 不依赖不可验证的 Token 阈值判断对话是否过长。

## 导出流程

1. 识别当前唯一主任务。
2. 将其余相关内容分类为旁支事项。
3. 收集最小必要项目事实，不全量扫描仓库或对话。
4. 区分已验证事实、旧对话判断和待确认事项。
5. 检查 Git、关键文件、验证结果和运行状态。
6. 自动选择 `quick` 或 `full`。
7. 输出结构化交接摘要。
8. 输出可直接用于新对话的启动提示词。
9. 仅在用户明确要求时覆盖 `.codex/handoff/current.md`。

## 接手流程

用户在新对话中粘贴交接摘要，或者使用：

```text
读取 .codex/handoff/current.md，验证当前状态后继续任务。
```

同一个 handoff skill 进入接手模式：

1. 检查交接内容是否包含主任务、当前状态和下一步。
2. 检查交接时间、项目路径和适用范围。
3. 核对当前目录、Git 分支、工作区和关键文件。
4. 对高风险结论执行深入验证。
5. 输出相符项、变化项和无法验证项。
6. 根据风险决定继续、重新确认或停止。
7. 旁支事项保持未授权状态，除非用户明确提升为主任务。

## 风险分级验证

### 低风险差异

例如出现与主任务无关的新文件。说明变化后可以继续。

### 中风险差异

例如关键文档在交接后被修改，或验证结果已过期。重新读取相关事实，并在继续前说明调整后的下一步。

### 高风险差异

例如：

- 当前分支与交接分支不一致。
- 任务范围发生变化。
- 实现授权失效。
- 关键文件被其他任务修改。
- 权威需求、设计或任务文档与摘要冲突。
- 交接要求继续编码，但当前验证或阶段条件不满足。

公司版必须停止并要求确认。个人版也不得静默继续，应说明风险并等待用户决定。

## 文件策略

- 默认不创建交接文件。
- 用户明确要求后，写入 `.codex/handoff/current.md`。
- 再次生成时覆盖当前文件，不累积按日期命名的交接文件。
- `current.md` 默认作为本地运行状态，不加入 Git。
- 团队共享或正式里程碑归档必须由用户明确要求，并使用项目既有文档规则。
- Skill 不自动修改 `.gitignore`，避免未经授权改变项目策略。

## 异常处理

- 当前目录不是交接目标项目：停止并提示切换目录。
- 项目没有 Git：跳过 Git 检查，并标记版本状态未验证。
- 摘要缺少主任务或下一步：先补齐，不能直接执行。
- 粘贴摘要与 `current.md` 冲突：用户本轮内容作为候选，项目事实作为最终依据。
- 交接时间过旧：说明时间差并重新验证关键状态。
- 关键文件不存在或已变化：输出差异，不静默继续。
- 检测到同文件并发修改：公司版停止确认；个人版说明风险后等待决定。

## 与现有 Skills 的关系

- `company-context-index`：继续负责项目级长期导航，不承载临时对话状态。
- `personal-memory-index`：继续负责可长期复用的个人项目记忆，不承载一次性接手状态。
- `company-workflow-help`：识别交接提醒时机并路由到 `company-thread-handoff`。
- `personal-workflow-help`：识别交接提醒时机并路由到 `personal-thread-handoff`。
- 需求、设计、任务、实现、bugfix 和 spike skills：在阶段结束但任务未结束时，可以建议生成交接摘要。
- 交接摘要不产生新的实现授权，也不替代阶段确认。

## 验证设计

至少覆盖以下场景：

1. 纯讨论对话生成 `quick` 摘要，不创建文件。
2. 存在未提交代码和未运行测试时生成 `full` 摘要。
3. 旁支事项被标记为未授权，不进入下一步。
4. 新对话发现分支变化时停止实现。
5. 新对话发现无关低风险变化时说明后继续。
6. 用户要求落盘时只维护 `.codex/handoff/current.md`。
7. 再次落盘时覆盖当前交接，不制造历史文件。
8. 公司版包含阶段授权、验证证据和能力调用信息。
9. 个人版默认保持精简，不强制输出完整审计字段。
10. 缺少 Git 时仍能生成交接，但明确未验证项。

## 成功标准

- 新对话一次读取后能说明当前主任务、进度和下一步。
- 新对话不继承过期实现授权。
- 旁支讨论不会自动变成当前任务。
- 用户不需要重新复制或读取完整旧对话。
- 默认不增加项目文档数量。
- `quick` 输出明显短于完整聊天记录。
- 项目事实与摘要冲突时，始终以重新验证的项目事实为准。
- 公司版和个人版共享核心协议，但不会因公司审计字段拖慢个人任务。

## 非目标

- 不自动创建 Codex 新任务。
- 不自动向其他任务发送消息。
- 不保存完整聊天记录。
- 不建立长期知识库或替代 Codex memory。
- 不自动提交交接文件到 Git。
- 不通过固定 Token 数判断何时切换对话。
